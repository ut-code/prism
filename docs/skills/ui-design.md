# UI デザイン原則

## コア哲学

**意図性 > 強度** — 明確な方向性を選び、精密に実行する。

## デザイン思考

コードを書く前に、大胆な美的方向性を決める:

1. **目的**: 何を解決する？誰が使う？
2. **トーン**: 極端を選ぶ（ミニマル、マキシマリスト、レトロ、ラグジュアリー、プレイフル、エディトリアル、ブルータリスト...）
3. **差別化**: 何が記憶に残る？

## Prism デザイン言語: "Clarity"

### コンセプト

プリズムが光を分解し本質を見せるように、**情報の透明性と明瞭さ**を追求する。

コミュニケーションツールにおいて、UIは「消える」べき存在。ユーザーが意識するのはコンテンツと人であり、インターフェースではない。

### 原則

| 原則       | 説明                                             |
| ---------- | ------------------------------------------------ |
| **透明性** | UIは背景に溶け込む。主役はコンテンツ             |
| **静寂**   | 過度な装飾を排除。沈黙が信頼を生む               |
| **リズム** | 一貫した余白とタイポグラフィで視覚的な流れを作る |
| **光彩**   | 控えめなアクセントカラーで状態を示す             |

### カラーシステム

```
ベース:      中立的な白/グレー (base-100, base-200, base-300)
コンテンツ:   高コントラストの黒/白 (base-content)
アクセント:   スペクトラルな色相（状態表現に限定使用）
             - primary: アクション、フォーカス
             - success/warning/error: フィードバック
```

**禁止**: 派手なグラデーション、ネオン、過度な影

### タイポグラフィ

- 本文: 可読性最優先。適切な行間 (1.5-1.6)
- 見出し: 控えめなウェイト差。叫ばない
- コード/等幅: 明確な区別

### モーション

- **微細**: フェード、軽いスライドのみ
- **目的**: 空間的な連続性を示すため（装飾ではない）
- **速度**: 150-250ms。存在を意識させない

### 空間

- 余白は贅沢に使う
- 情報密度は低めに保つ
- グループ間は明確に分離

### コンポーネント指針

| 要素     | 方針                                                  |
| -------- | ----------------------------------------------------- |
| ボタン   | ゴースト/アウトラインを優先。塗りは主要アクションのみ |
| カード   | 影は最小限。境界線か背景色で区別                      |
| 入力     | ボーダーは薄く。フォーカス時のみ強調                  |
| モーダル | 背景を暗くしすぎない。内容に集中させる                |

## ミニマルデザイン原則

### 削ぎ落とす

> "完璧とは、付け加えるものがなくなった時ではなく、取り除くものがなくなった時に達成される" — サン=テグジュペリ

- 要素を追加する前に「これは本当に必要か？」と問う
- 1つの要素が複数の役割を果たせるなら、統合する
- 装飾は機能を持つ時だけ許容される

### 引き算の美学

| 削除対象         | 理由                           |
| ---------------- | ------------------------------ |
| 不要なラベル     | アイコンや文脈で明らかなら省く |
| 冗長なボーダー   | 余白だけで区切れるなら不要     |
| 説明テキスト     | UIが直感的なら説明は要らない   |
| 確認ダイアログ   | 取り消し可能なら確認不要       |
| ローディング表示 | 200ms以内なら見せない          |

### 制約から生まれる創造性

- 色数を絞る（3色以内）
- フォントは2種類まで
- アニメーションは1種類の動きに統一
- 余白のサイズは4pxの倍数に限定

### 静かなUI

- デフォルト状態は最も控えめに
- ホバー/フォーカスで情報を段階的に開示
- エラーや警告以外でユーザーの注意を奪わない
- 通知は本当に必要な時だけ

---

## アンチパターン

- ジェネリックフォント（Arial, Roboto, システムフォント）
- 陳腐な配色（白背景に紫グラデーション）
- 予測可能なレイアウト
- 装飾目的のアニメーション
- **UIが主張しすぎる設計**

---

## 指針

**複雑さはビジョンに合わせる:**

- マキシマリスト = 精巧なコード、豊富なアニメーション
- **ミニマリスト (Prism)** = 抑制、精密さ、余白、タイポグラフィ、微細なディテール
